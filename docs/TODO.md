## 0. 优先级定义与验收原则

| 优先级 | 定义 | 处理规则 |
|---|---|---|
| **P0** | 阻断核心闭环，或造成不可逆数据损失 | 不等排期，先修；未清空 P0 不启动任何新功能 |
| **P1** | 显著影响可用性、信任或核心场景 | 当期版本内完成 |
| **P2** | 体验打磨与能力扩展 | 按 RICE 排序进入后续版本 |

**验收标准三条硬规则：**

1. **可执行**：必须能写成一个断言或一段 30 秒的人工复现脚本，不写"体验更好"这类无法验收的描述。
2. **含边界**：任何"可配置上限"类功能，验收必须包含"上限处仍然可用"的用例（v1.1.0 的 D-01 就是栽在这里）。
3. **含失败态**：必须写明失败时用户看到什么、能做什么。

## M1 · 数据与库存内核

> 目标：让 `qty` 从"一个数字"变成"有据可查的账"。

- [x] **T-M1-01 库存流水表（P0 · 2.5d · 依赖：无）**【已完成 2026-11-07,实际 1.5d】
  - 新增 `stock_moves(id, device_id, delta, before_qty, after_qty, source, ref, cell, note, created_at)`；`source ∈ {manual, box_take, box_return, import, adjust, undo}`。
  - `devices.adjust_qty` / 导入 / 手工改数量，**全部**改为"写流水 + 更新 qty"，同一事务内完成。
  - 验收：任意一次库存变化，都能在 `stock_moves` 查到 `before→after`；并发两次取料不丢记录。
  - 反例验收：手工改数量若只改了 `qty` 未写流水 → 断言失败。

- [x] **T-M1-02 流水查询与撤销（P0 · 2.0d · 依赖 T-M1-01）**【已完成 2026-11-07,实际 1.0d,撤销按钮置于器件编辑弹窗】
  - 接口 `GET /api/devices/<id>/moves`（分页）、`POST /api/moves/<id>/undo`（按反向 delta 回滚，写一条 `undo` 记录，不删除原记录）。
  - 前端：器件详情抽屉 → 流水时间线（时间/来源/Δ/结余/备注）。
  - 验收：撤销一条 `-1` 取料后 qty 回到原值，期间所有记录仍存在（只增不删）。

- [x] **T-M1-03 软删除与操作快照（P0 · 2.0d · 依赖：无）**【已完成 2026-11-07,实际 1.5d;回收站 UI 延后至 v1.2.0,软删数据可经备份找回】
  - `devices` 加 `deleted_at`；删除改为软删，列表默认过滤。
  - 映射/批量操作前写 `snapshots(id, kind, payload_json, created_at)`，保留最近 10 条。
  - 接口 `POST /api/snapshots/<id>/restore`；前端"撤销上一步"按钮 + 回收站（30 天后可清空）。
  - 验收：清空 63 格映射 → 点撤销 → 63 格映射完全复原（含器件绑定）。

- [x] **T-M1-04 备份与恢复（P0 · 1.0d · 依赖 T-M1-01/03）**【已完成 2026-11-07,实际 1.0d】
  - `GET /api/backup/export` → zip（`pdl.db` 一致性快照 + `manifest.json` 含版本/时间/映射/硬件配置）；`POST /api/backup/import` → 校验版本与 schema 后恢复，**恢复前自动先备份当前库**。
  - 启动时自动日备份至 `backups/`，保留 7 份。
  - 验收：备份 → 删除数据目录 → 恢复 → 器件/映射/硬件配置/流水条数完全一致。

- [ ] **T-M1-05 低库存阈值与补货清单（P1 · 1.5d · 依赖：无）**
  - 阈值配置移到 `box_config`（或 settings 表），默认 10；`GET /api/devices?stock=low|zero`。
  - 补货清单页：器件/当前量/建议采购量/参考单价 → 导出 CSV。
  - 验收：阈值改为 20 后，19 件的器件立即出现在低库存筛选中。

- [ ] **T-M1-06 schema 版本与迁移框架（P2 · 1.0d）**
  - 启用 `PRAGMA user_version`，迁移按版本号顺序执行，失败回滚并保留备份。
  - 验收：从 v1.1.0 旧库升级到含流水的版本，数据无损且 `user_version` 正确。

- [ ] **T-M1-07 器件查重提示（P2 · 1.5d）**
  - 新建/导入时按「型号 + 封装 + 品牌」归一化比对（无型号则按名称归一化），命中则提示"可能重复，合并 / 仍然新建"。

## M2 · 导入与价格

> 目标：导入不再制造错误数据，长任务不再像卡死。

- [x] **T-M2-01 导入幂等键（P0 · 1.5d · 依赖：无）**【已完成 2026-11-07,实际 1.0d,幂等键=文件 sha256】

  - 重复批次命中时：不写库，返回"该订单已于 X 时间导入（新增 N / 合并 M），是否仍要再次累加？"，用户显式确认后才走合并。
  - 验收：同一订单文件连导两次 → 第二次默认不改变任何 `qty`；强制确认后才累加。

- [ ] **T-M2-02 订单文件导入预览（P1 · 2.0d · 依赖 T-M2-01）**
  - 文件导入改为与 C 编号一致的两阶段（预览 → 确认），预览显示"识别 N 条 / 新器件 X / 将累加 Y / 无法识别 Z（附原因）"。
  - 验收：导入只含 2 个有效 C 编号的表格 → 预览准确显示 2/0/0；不含 C 编号的文件给出明确失败原因而非"未能识别"。

- [ ] **T-M2-03 长任务化与进度（P1 · 2.5d · 依赖：无）**

  - 验收：刷新 100 件时进度条从 0→100%，中途可关闭弹窗且任务继续，完成后有完成提示。

- [ ] **T-M2-04 价格与资产口径统一（P1 · 1.5d · 依赖：无）**
  - 明确两条口径：接口价（USD）与手填价（CNY），互不覆盖；设置项可填汇率（默认标注"参考汇率，非实时"）。
  - 资产总览分两栏统计（¥ 与 $），不做无依据的合并换算；标注统计时间与覆盖器件数。
  - 验收：同一页面同时存在 USD 与 CNY 器件时，总览分别显示两组数值与折算说明，不出现混算。

- [ ] **T-M2-05 导入历史界面与上传文件清理（P2 · 0.5d）**

  - 验收：导入历史页可见最近 50 次记录；`uploads/` 不再无限增长。

## M3 · 器件盒映射与联动

> 目标：63 格真的能用；找料从"人肉翻找"变成"点亮即见"。

- [x] **T-M3-01 sync 分批发送（P0 · 0.5d · 依赖 T-M4-01）**【已完成 2026-11-07,实际 0.5d】
  - `push_sync` 按每批 ≤8 条切分，逐条发送，每条加 `seq/total`；末批后发 `sync_end`。
  - **防御性设计**：`connect()` 中 `push_sync` 失败不再抛出阻断连接，改为"已连接（映射同步待重试）"，UI 明确提示并给重试按钮。
  - 验收：63 格全映射 → 连接成功 → `ready.mapped == 63`；断开重连后再次同步仍成功。

- [ ] **T-M3-02 映射操作可逆（P0 · 1.0d · 依赖 T-M1-03）**
  - `clear_box` / `auto_arrange` 执行前写快照；前端提供"撤销"。
  - 验收：一键排布覆盖原有 30 格自定义布局 → 撤销后逐格一致。

- [ ] **T-M3-03 同器件多格位约束（P1 · 1.0d · 依赖：无）**
  - 短期方案：同一器件分配第二个格位时提示"已在格位 #N，移动 / 复制（库存共享）"，并在格位卡片标注"共享"。
  - 若选"复制"，两格显示同一 qty（明确标注共享），消除当前显示不一致。
  - 验收：同一器件分配两格后，任一格取料两格数字同步变化。

- [ ] **T-M3-04 找料闭环（P1 · 1.0d · 依赖：无）**
  - 器件列表每行加"定位"：有映射 → 跳映射页并选中高亮 + 调 `/serial/light`；无映射 → 显示"未入盒"并提供"分配到格位"。
  - 映射页支持按器件名搜索过滤（仅高亮匹配格位）。
  - 验收：搜索"100nF" → 点定位 → 2 秒内对应格位在软件高亮且实体 LED 点亮。

- [ ] **T-M3-05 多盒数据模型设计（P2 · 3.0d · 仅设计不实现）**
  - 输出 `boxes(id, name, rows, cols, port, config_json)` + `mappings(box_id, row, col, device_id)` 的目标模型与迁移方案，含固件寻址字段。
  - 验收：产出一份可评审的设计文档，明确"改造成本、兼容策略、回滚路径"，**不写实现代码**。

- [ ] **T-M3-06 串口健壮性（P1 · 1.5d）**
  - 心跳：每 5s 发 `ping`，连续 3 次无 `pong` → 标记断开并按退避重连 3 次；拔插 USB 后自动恢复。
  - 验收：运行中拔掉 USB → 3 秒内 UI 显示"连接已断开"；插回后 5 秒内自动恢复且映射同步完成。

## M4 · 固件与协议

> 目标：协议能承载设计容量；库存不与格位号绑死。

- [x] **T-M4-01 协议分帧与增量 sync（P0 · 1.0d · 依赖：无）**【已完成 2026-11-07,实际 1.0d;顺带补齐文档已声明的 cursor/lit 事件】
  - `sync` 支持 `seq/total`：固件累加收到的 items，`seq == total` 时回 `ready{mapped: 累计}`；取消"超出即整行丢弃"的静默失败，改为回 `log` 错误事件。
  - 同时把单行上限提升到 1024 字节（RAM 足够），为后续扩展留余量。
  - 验收：63 格全映射 sync 成功，`ready.mapped == 63`；伪造超长行时主机能收到明确错误事件而非静默。

- [ ] **T-M4-02 映射指纹与 NVS 重置（P1 · 1.5d · 依赖：无）**
  - 生成 `box_config.h` 时写入 `#define BOX_CONFIG_FINGERPRINT "<sha256 前 8 字节>"`；固件启动比对 NVS 中指纹，不一致 → 清空全部格位库存 → 写入新指纹并 `send_log("config changed, stock reset")`。
  - 验收：改映射（格位 5 换器件）后重烧 → 格位 5 库存等于新配置初值，不继承旧值；OLED/日志有明确提示。

- [ ] **T-M4-03 固件内器件定位（P1 · 2.0d · 依赖：无）**
  - 五向键增加"按首字母跳格"或"长按进入搜索"（OLED 显示名称前缀），解决 63 格逐格移动的痛点。
  - 验收：63 格满映射下，从格位 0 移到任意格位不超过 6 次按键。

- [ ] **T-M4-04 空闲熄灯与亮度策略（P2 · 1.0d）**
  - 无操作 60s → 全部熄灯（仅保留光标格微亮）；任意按键唤醒；亮度上限可配。
  - 验收：静置 60s 后 LED 全灭，按键立即恢复；实测电流下降。

- [ ] **T-M4-05 二维码/格位标签数据支持（P2 · 1.0d · 依赖 T-M4-02）**
  - 固件 `hello` 返回指纹与格位映射摘要，供软件校验"盒子烧的是不是当前映射"。
  - 验收：烧了旧固件时软件连接后提示"固件映射与当前不一致，建议重新生成烧录"。
